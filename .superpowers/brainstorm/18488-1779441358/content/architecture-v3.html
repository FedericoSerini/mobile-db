Device Key Lifecycle — 1 active key per device
Table: device_keys
┌─ device_key_id (uuid PK)
├─ device_id (stable id)
├─ app_id (tenant)
├─ key_hash (bcrypt)
├─ status: active | revoked
├─ registered_at
└─ last_seen_at
Registration (first launch):
1. Device sends { app_id, device_id }
2. Server issues { device_key_id, secret }
3. Client stores in secure enclave

Rotation (atomic, no grace period):
1. Client generates new secret
2. POST /devices/rotate-key { old_secret, new_secret }
3. Server atomic swap — instant
JWT tokens:
Access token: 15min TTL
Refresh token: 30d, one-time use
Refresh rotates on each use
Reuse detected → revoke all tokens

Remote wipe:
DELETE /devices/:id
→ status revoked
→ device cannot sync
Data Segregation Model
app_id = tenant namespace
device_id = registered device
user_id = user within tenant
dataset_id = logical collection
doc_id = individual JSON document
Path: app/user/dataset/doc
SQLite table: one per dataset
No cross-tenant data leakage
Each doc = independent CRDT
Delta Sync Flow
1. Client writes locally → CRDT ops appended to local log
2. On sync: client sends { clock, ops[] } compressed with Zstd
3. Server merges ops, computes diff vs client clock
4. Server replies with { new_clock, server_ops[] } compressed
5. SSE channel notifies other clients → they pull delta
6. Periodic compaction: ops log → snapshot (reduce storage)
