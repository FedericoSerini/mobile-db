Three Architectural Approaches

Pick the foundation — everything else is built on this choice

A

Automerge Stack

CRDT: Automerge library (battle-tested, JSON-native)
Server: Node.js + SQLite
Client: automerge-repo (handles local storage + sync)
Delta format: Automerge binary (built-in, compact)
Compression: Zstd over the wire

Pros

  • CRDT already solved — no custom merge logic
  • automerge-repo handles offline + sync loop
  • Active community, good docs

Cons

  • Heavy JS dependency (WASM on some platforms)
  • Harder to port to native mobile (Swift/Kotlin)
  • Less control over wire format
B

Go Backend + cr-sqlite Client

CRDT: cr-sqlite (SQLite extension with CRDT merge)
Server: Go (small binary, easy Docker deploy)
Client: cr-sqlite on device (iOS/Android/Web via WASM)
Delta format: Merkle-clock based operation log
Compression: CBOR + Zstd

Pros

  • SQLite = battle-tested storage everywhere
  • Go server = single binary, trivial deployment
  • CRDTs at DB level — works across SQL queries too

Cons

  • cr-sqlite is newer, less mature than Automerge
  • SQLite WASM on web adds ~3MB bundle
  • JSON structure queries need JSON1 extension
C

Custom Lightweight CRDT

CRDT: Hand-rolled LWW-Register + OR-Set for JSON
Server: Go or Rust (max portability)
Client: SQLite (any platform) + custom sync engine
Delta format: JSON Patch (RFC 6902) compressed with Zstd
Compression: MessagePack or CBOR + Zstd

Pros

  • Full control — tune merge semantics per dataset
  • No WASM dependency, ports to any platform
  • Minimal footprint on device

Cons

  • You write and maintain the CRDT logic
  • Edge cases in merge are subtle and hard to test
  • Longest to build correctly

My recommendation: B — Go + cr-sqlite gives you a single deployable binary on the server, SQLite everywhere on clients (iOS has it natively, Android has it natively, Web gets WASM), and CRDT merge is handled at the storage layer so your sync protocol stays simple. Automerge (A) is the fastest to a working prototype but the WASM story on native mobile is painful.
